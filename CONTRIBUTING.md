# Как работаем в команде

## Роли и зоны

| Роль | Зона | Папка | Своя метрика |
|---|---|---|---|
| 1. Данные | парсеры, OCR, чанкинг, метаданные | `src/ingest/` | все файлы распарсены, у каждого чанка есть `page` и `location` |
| 2. Поиск | эмбеддинги, BM25, гибрид, reranker | `src/retrieve/` | hit@3, MRR |
| 3. Генерация | LLM, промпт, порог, confidence, источники | `src/generate/` | доля верных отказов, факты в ответе |
| 4. Роутер и оценка | правила, NCM, тест-сет, метрики | `src/router/`, `eval/` | точность роутера, общая таблица метрик |
| 5. Сборка и демо | пайплайн, API, Docker, README, видео | `src/pipeline.py`, `src/api.py`, корень | `docker compose up` за 10 минут, ответ < 5 с |

Если вас четверо: роутер забирает роль 2 (тот же эмбеддер), оценку — роль 3.

## Контракты

Все модули общаются через `src/schema.py`: `Chunk` (фрагмент + метаданные), `Hit` (фрагмент + скор),
`Route` (какие компании). Меняем его только по договорённости всей команды, отдельным PR.

## Git

**Один раз:**
```bash
git clone https://github.com/<организация>/rag-hackathon.git
cd rag-hackathon
```

**Каждая задача:**
```bash
git switch main && git pull                 # свежий main
git switch -c feat/router-ncm               # ветка под задачу: feat/..., fix/...
# ... работа, тесты: pytest -q
git add src/router
git commit -m "router: NCM разбивает ничью правил"
git push -u origin feat/router-ncm
```
Дальше на GitHub: **Compare & pull request**, затем ревью владельца папки, CI зелёный, **Squash and merge**, ветку удалить.

**Ветка живёт дольше дня:** `git fetch && git merge origin/main`, чтобы не копить конфликты.

## Правила

- `main` всегда рабочий: тесты проходят, `docker compose up` поднимается.
- Никогда не делать `git push --force` в `main`.
- Один PR = одна задача (несколько часов работы, не весь день).
- Не коммитить: модели, `docs/`, `index_data/`, `.env`, ключи. Всё это уже в `.gitignore`.
- Настройки под себя меняем в `.env`, а не в `src/config.py`.
- Новая библиотека в `requirements.txt` — отдельным маленьким PR с точной версией.
- Новый модуль — вместе с тестом в `tests/` (модели в тестах фейковые, см. `tests/conftest.py`).
- Перед хакатоном ставим тег: `git tag pre-hackathon && git push --tags`.
- На хакатоне: заморозка фич за 4–5 часов до сдачи, дальше только исправления и упаковка.
