# Соответствие ТЗ: что сделано и что осталось

Каркас закрывает все обязательные требования ТЗ и оба бонуса. На хакатоне остаются три вещи:
настройка на реальных данных (порог, ключевые слова, чанкинг), замер скорости на CPU и упаковка
(видео, питч, проверка Docker на чистой машине).

Статусы: ✅ готово и покрыто тестом · 🟡 есть, но нужно проверить или настроить на данных · ⬜ сделать на хакатоне.

## 1. Бизнес-требования (раздел 2 ТЗ)

| № | Требование | Как сделано | Где | Статус |
|---|---|---|---|---|
| 1 | Точность, без галлюцинаций; нет данных — «нет в документах» | Порог по скору reranker: ниже `MIN_CONFIDENCE` отказ без вызова LLM. Промпт требует точную фразу отказа. Если LLM отказала, источники пустые, confidence ≤ 0,2. Самопроверка: числа из ответа, которых нет в документах, снижают confidence вдвое и ставят пометку «не уверен» | `generate/answer.py`, `generate/prompt.py`, `pipeline.py` | ✅ логика · 🟡 порог подобрать на вопросах |
| 2 | Ответ не дольше 5 с | LLM 3B по умолчанию, 3 фрагмента контекста, ответ ≤ 150 токенов, кэш, прогрев моделей при старте, отказ без LLM, векторный поиск за миллисекунды (numpy). Время по каждому шагу в `?debug=true` | `config.py`, `pipeline.py` | 🟡 замерить на CPU 4 ядра / 16 ГБ |
| 3 | Прозрачность: документ, страница/абзац, confidence 0–1 | `sources: [{doc, page, score}]`, `page` всегда число: страница PDF, абзац DOCX, строка XLSX/CSV, запись JSON. Подпись «абзацы 3–9» / «Тарифы, строка 7» в `location`. Источники — те фрагменты, которые LLM процитировала | `schema.py`, `generate/answer.py` | ✅ |
| 4 | Форматы: PDF (текст и сканы), DOCX, CSV, TXT, изображения с таблицами | PDF постранично + OCR при пустом текстовом слое; DOCX с заголовками-разделами и таблицами на своём месте; XLSX/CSV строка = чанк с шапкой (ищет настоящую шапку под строкой-заголовком); JSON — записи на любой глубине; MD по разделам; PNG/JPG через OCR | `ingest/parsers.py` | ✅ · 🟡 таблица с картинки идёт текстом, без структуры |
| 5 | Разграничение по компании | Роутер: ключевые слова (с начала слова) → NCM по центроидам документов компаний → иначе все компании. Если в выбранной компании ничего уверенного — повторный поиск по всем | `router/`, `pipeline.py` | ✅ · 🟡 пополнить ключевые слова по данным |

## 2. Критерии оценки (раздел 5 ТЗ)

| Критерий (вес) | Что проверяют | Что у нас есть | Что сделать на хакатоне |
|---|---|---|---|

Своя оценка: hit@1/@3, MRR, точность роутера, доля верных отказов, факты в ответе (`eval/evaluate.py`) | Разметить публичные вопросы в формате `eval/questions.example.json`; прогнать `eval_script.py` организаторов (RAGAS); подобрать `MIN_CONFIDENCE`; разбор промахов |
| Воспроизводимость (20) | `docker-compose up` или README, подъём за 10 минут | Docker: модели эмбеддингов и reranker внутри образа, LLM качается один раз, API ждёт готовности модели (healthcheck). Версии библиотек закреплены. README с шагами. CI с тестами | Проверить `docker compose up --build` на чистой машине и засечь время; закрепить версию образа Ollama; решить, отдаём ли готовый индекс в `index_data/` |
| Скорость (10) | Среднее время на CPU ноутбука жюри: < 2 с — 10, 2–5 с — 7 | См. требование 2. Время по шагам видно в debug и в веб-интерфейсе | Замер `eval/evaluate.py --full` на CPU. Если > 5 с: модель 1.5B, `TOP_K_RETRIEVE=8`, `TOP_K_CONTEXT=2` |
| Форматы и метаданные (15) | Ответы по XLSX, номер страницы из PDF, уверенность | Строка таблицы = чанк с названиями колонок; номер строки как в Excel; страница PDF; confidence | Расчёт по тарифной сетке с диапазонами веса (ветка с pandas/SQL в обход LLM), если в данных такие таблицы |
| Креативность (15) | Гибрид, автоопределение компании, кэш, веб-интерфейс, голос, «я не уверен» | Все шесть: BM25 + векторы с RRF, роутер правила + NCM, LRU-кэш, веб-страница, голосовой ввод (Chrome), пометка «Я не уверен» | Показать на демо; для голоса офлайн — локальный Whisper (по желанию) |

## 3. Бонусы

| Бонус | Статус | Как сделано |
|---|---|---|
| Reranker (раздел 4) | ✅ | `BAAI/bge-reranker-base`, top-12 → лучшие 3 |
| A. Agentic RAG | ✅ | Маленький классификатор без LLM: правила + NCM на центроидах (k-means по 3 центроида на компанию). Поиск только в выбранной компании, при низкой уверенности — второй проход по всем |
| B. `/update` | ✅ | Загрузка файла через форму или `curl`, инкрементальная переиндексация только этого файла, сброс кэша и пересчёт центроидов роутера |

ТЗ засчитывает один бонус (до +10). На питче основной — A, он же закрывает требование 5; B показываем как дополнительную фичу.

## 6. Что изменено относительно черновика и зачем

| Изменение | Зачем | Пункт ТЗ |
|---|---|---|
| Код разложен по папкам владельцев, общий контракт в `schema.py`, `CODEOWNERS`, CI | 5 человек работают параллельно без конфликтов | организация работы |
| `POST /ask` по умолчанию отдаёт строго `answer/sources/confidence`, расширенные поля только в `?debug=true` | Автопроверка жюри не споткнётся о лишние поля | раздел 6 |
| `page` всегда число; подпись вынесена в `location` | В черновике `page` бывал строкой («абзацы 3–9»), а в ТЗ это число | 2.3, 6 |
| Источники берутся по цитатам [n] из ответа LLM, а не просто топ-3 | Источник указывает на фрагмент, из которого взят ответ | 2.3 |
| Самопроверка чисел ответа против документов | Ловит самую опасную галлюцинацию (выдуманная цифра), даёт «я не уверен» | 2.1, 5 (креатив) |
| Роутер: слова ищутся с начала слова; NCM разбивает ничью и решает, когда правила молчат; повторный поиск по всем компаниям | «чат» больше не срабатывает внутри «начать»; ошибка роутера не убивает ответ | 2.5, бонус A |
| Шапка «компания · файл · раздел» добавляется к тексту чанка при индексации | Поиск находит фрагмент по названию документа и раздела | 5 (точность) |
| DOCX: разделы по заголовкам и пунктам договора, таблицы на своём месте | «Есть ли в договоре пункт о штрафах» находит раздел про штрафы | 2.4 |
| XLSX/CSV: поиск настоящей шапки под строкой-заголовком, номер строки как в Excel | Реальные тарифные таблицы часто начинаются с названия, а не с шапки | 2.4, 5 (форматы) |
| JSON: записи на любой глубине, вложенные поля разворачиваются | Карточки товаров бывают вложены (`catalog.items`) | 2.4 |
| BM25 свой: русский стемминг окончаний, коды «ТП-400» = «TP-400» = «ТП 400» | Точные названия моделей и артикулов — частые вопросы | 5 (гибридный поиск) |
| Qdrant заменён на numpy-хранилище | На ~20 тыс. чанков поиск за миллисекунды, нет блокировки «один процесс», на один сервис в Docker меньше | 2.2, 5 (воспроизводимость) |
| `LLM_MAX_TOKENS` 300 → 150, `TOP_K_CONTEXT` 4 → 3, прогрев моделей при старте | Ниже время ответа на CPU, первый вопрос жюри не ждёт загрузку | 2.2, 5 (скорость) |
| `/update` только загрузкой файла (без скачивания по URL) | Скачивание по URL позволяло обращаться к внутренним адресам сервера | бонус B |
| Docker: модели в образе, healthcheck, API ждёт готовности LLM; версии библиотек закреплены | Подъём у жюри без долгих загрузок и «у меня работало» | 5 (воспроизводимость) |
| `.env` реально читается при локальном запуске | В черновике `.env` создавался, но нигде не загружался | README |
| Оценка: + точность роутера, hit@1, MRR, факты в ответе, p50/p95 времени | Цифры для питча и для выбора настроек | раздел 9 |
| Тесты разбиты по модулям и запускаются `pytest` (30 проверок) | Каждый владелец проверяет свою зону, CI не пускает поломки в `main` | организация работы |
